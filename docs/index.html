Parallel Image Processing
with Python & Flask

A web app that compares serial vs. parallel Canny edge detection using Python's multiprocessing module. Built for IFB 206 Komputasi Paralel, Semester Genap 2025/2026.

Python 3 Flask OpenCV multiprocessing NumPy

Architecture

The image is split into 4 horizontal chunks, each processed by a separate worker process in parallel, then merged back into one result.

User (Browser) │ ▼ Flask Web Server (app.py) │ ├── Serial: cv2.Canny(full_image) │ └── Parallel: multiprocessing.Pool(4) ├── Worker 1 → cv2.Canny(chunk_1) ├── Worker 2 → cv2.Canny(chunk_2) ├── Worker 3 → cv2.Canny(chunk_3) └── Worker 4 → cv2.Canny(chunk_4) └── np.vstack() → merged result

How It Works

1

Upload — user uploads an image through the web form. Saved to static/uploads/.

2

Split — image loaded as grayscale, divided into 4 chunks with numpy.array_split.

3

Process — each chunk processed in parallel via multiprocessing.Pool(4). Serial run also timed for comparison.

4

Merge — results stacked with np.vstack, saved to static/results/, displayed with timing data.

Core Code

def process_chunk(chunk):
    return cv2.Canny(chunk, 100, 200)

# Split
chunks = np.array_split(image, 4)

# Parallel
with Pool(4) as pool:
    processed = pool.map(process_chunk, chunks)

# Merge
result = np.vstack(processed)

Parallelism Theory

This project demonstrates task parallelism — dividing independent work across multiple CPU cores. The theoretical maximum speedup follows Amdahl's Law: 

S = 1 / ( (1 - P) + P/N )

  S = speedup
  P = parallelizable portion of the task
  N = number of processors (4 in this project)

In practice, overhead from process spawning and memory copying reduces actual speedup, especially on small images. Results are more visible with larger input files.
